## PRD 摘要

目标：让用户准确知道任务是否已保存，失败后无需重新输入，也不产生重复任务。用户：Chrome Popup 与新标签页任务新增、编辑使用者。核心：明确本地保存结果、防重复提交、失败保留内容、安全重试。视觉：沿用现有表单与反馈组件，错误在表单内可见，不新增页面。约束：本地与云端成功语义分开，保护既有账号同步、访客可用和任意日期排期。参考：同项目已有父子任务创建的保存失败保护；无需引入竞品功能。

## 包含与不包含

包含普通任务新增及编辑的提交链路、保存过程中重复提交保护、失败保留内容、同一操作安全重试、本地成功与云端失败的正确表达。父任务编辑若共用相同有缺陷提交链路，需保持同样的保存结果保护；已有父子任务创建保护不得退化。

不包含持久草稿（UX-02）、快速添加/默认任务池（UX-05）、新增后的去向提示（UX-03）、筛选、周视图及其他任务操作的全量重构。不得把本次修复扩大到整个保存架构或云端协议迁移。

## 用户流程与状态

1. 用户填写表单，点击保存；立即出现保存中反馈并阻止同一操作重复提交。期间保留输入，避免取消操作导致半保存状态。
2. 本地持久化确认成功：结束本次编辑，沿用正常更新列表流程；已在本机保存与云端同步状态各自准确。
3. 本地持久化失败：表单保持打开、内容不清除、按钮恢复可操作，显示“本地保存失败，内容已保留，请重试”。错误不能仅藏在顶部同步图标。
4. 点击重试：保存同一条任务；修正错误再试也不创建额外记录。开发根据当前状态管理决定回滚本次内存变更或复用稳定任务身份，保护操作开始后其他入口/同步产生的合法变更。
5. 本地成功、云端失败：任务仍为已在本机保存，不要求重复新增，不撤回已成功本地数据。

## 数据边界

只改变本次任务和相关提交状态。不得以整库旧快照回滚覆盖其他任务、分类、账号或同步修改。不得清除原有任务、修改扩展 key/ID、覆盖历史目录源码或打印真实任务/凭证。源码主工作区有其他未提交修改，必须隔离并精确提交。

## 验收

1. 普通新增模拟本地保存抛错：表单仍打开，全部输入保留，错误可见，保存按钮可再次操作；不得显示本地已保存成功。
2. 同一新增失败后重试成功：持久化只有一条任务；标题和所有用户属性准确。连续失败再成功也不重复。
3. 普通编辑保存失败后重试：仍修改原任务，未创建新记录；失败重试过程中其他任务的合法变更不被覆盖。
4. 快速连续点击保存：只有一次有效提交，不重复新增；正常成功可以完成表单流程。
5. 本地成功但云同步失败或离线：任务存在于本地，用户可继续使用；不把本地成功说成保存失败。
6. Popup 与新标签页共享路径均覆盖。已有父子任务创建保护、编辑、循环任务表单、已完成输入、任意过去日期不退化。
7. 构建后交付包可核对到新分支逻辑与版本；未进行 GUI/真人视觉验证须准确标记，不能仅依据源码宣告用户已获得修复。
