# 新电脑登录后无法恢复任务，云端拉取缺少恢复引导

- 状态：已记录，待修复；本次仅记录需求，未授权进入实现或部署。
- 优先级：P1（迁移后阻断用户继续使用）。
- 记录日期：2026-09-30；观察版本：3.16.0。
- GitHub Issue：待实现前关联独立 Issue。

## 用户目标与影响

用户在新电脑登录原有账号并加载新版扩展后，希望直接获取已有云端任务。实际看到空数据，点击“从云端拉取”未恢复，无法判断是任务丢失、认证失败还是未配置连接。恢复最终需要管理员导出 D1，再手动导入 JSON，超出普通用户应承担的操作成本。

## 已确认事实与诊断边界

- 迁移包恢复了代码，未包含可用的最新扩展业务数据；旧本机快照只有 66 条任务，不能代表当前数据。
- Chrome/Cloudflare 账号登录与 TaskMaster Worker API 认证是不同链路。新扩展未配置 `tm_sync_settings` 中的 API 地址/令牌；`shared/storage.ts` 在配置缺失时返回“未配置同步设置”。Cloudflare 授权可用于管理 D1，并不会自动赋予扩展 API 访问能力。
- Chrome 配置曾有两个不同 ID 的 TaskMaster 入口，对应不同本地存储；用户已移除旧入口。不能据此认定 ID 差异是本次失败的唯一原因。
- 3.16.0 的“从云端拉取”调用增量收敛，也可能提交本地变更；名称暗示的单向读取与实际行为不一致。
- 本次只读查询/导出 D1 确认有 186 条有效任务、5 个有效分类；46 条已删除任务未导入；手机队列没有未同步项。用户确认 JSON 导入成功，导入后数量未独立核验。
- 尚未获取用户点击时的完整响应/日志，不能声称已确认所有失败原因。手动导入成功也不代表跨设备同步恢复。

## 期望行为

1. 新设备进入同步入口时，自动判断本地数据、云端连接配置与认证状态，准确显示“已保存到本机”“尚未连接任务云端”“认证失效”“网络不可达”等状态，并提供可执行的下一步。
2. 普通用户应通过产品内的连接/认证与恢复引导获取已有数据，无需进入 Cloudflare 控制台、执行 SQL 或手填数据库 ID。具体身份关联方式留待设计确认；不得将 Chrome/Cloudflare 登录误称为 TaskMaster 已认证。
3. “从云端拉取”应先读取并恢复云端内容，读取阶段不提交本地任务、设置或删除；自动双向收敛使用明确的“同步”语义。存在本地不同数据时先备份并明确合并结果，不静默覆盖。
4. 连接缺失或认证失败时，拉取入口应直接引导连接或重新认证，保留已有本机数据；云端为空与连接失败不能使用相同反馈。
5. 恢复完成显示任务/分类数量及结果；本机导入成功和持续云端同步已启用分别展示。

## 验收标准

- 同一用户的新设备完成产品内认证后，可恢复云端任务和分类，保留 ID、完成状态、日期及删除语义；以固定测试数据验证数量，不把本次 186/5 写死。
- 缺配置、401/403、网络失败、云端为空均有不同反馈与下一步，不显示恢复成功。
- 云端读取阶段无业务写入；本地已有未同步记录时，恢复前有可恢复备份，既有数据不静默丢失。
- 两个不同扩展 ID 的场景不依赖共享本地存储完成云端恢复。
- 拉取成功后重新打开扩展仍保留数据；另一次自动同步不复活删除记录。
