## PRD 摘要

目标：随手记录时只填标题即可保存，不被默认排期和估时干扰。用户：个人日常使用扩展及手机添加入口。核心：简化默认新增表单、无日期进入任务池、保留用户明确选择、未估时不自动填一小时。视觉：沿用现有控件、颜色与文案，其余选项通过“更多”渐进展开。参考：现有 TaskMaster 表单与任务池，不引入新竞品功能。

## 范围与流程

1. 扩展 Popup、新标签页一般新增及手机添加：初始突出标题、可选计划日期、保存；备注、优先级、分类、硬截止、预计时长和重复等现有配置收于更多选项。保留现有任务模式名称与能力，编辑表单不强行重设计。
2. 一般入口新增不预填今天；未选择计划日期保存为任务池任务。用户在明确某日的入口触发新增，可以继承该日期；不能把仅处于今天视图当作明确选择。
3. 用户主动选择日期后按所选日期保存，包括任意过去日期；普通、特殊、大任务子项、任务池改期不增加日期限制。子项未选日期也允许进入任务池，父子关系保留；不在本项重做父子管理。
4. 未填写预计时长表示未估时，不默认一小时。沿用兼容数据表达，优先使用既有叶子任务 duration=0，界面展示空值或未估时，不把它说成实际零工作量。已有正数估时不回写、不迁移；父任务容器不计作未估时。
5. 更多选项折叠只影响展示，不清除字段、不让隐藏 required 阻塞提交。恢复草稿与编辑任务保持已填日期、估时、模式及其余值，继承 #69/#70 的保存失败及草稿保护。
6. 重复任务仍需用户明确选择首个计划日期；缺少时展开相关字段并给出可执行反馈，不偷偷赋今天。原有日期与重复校验保留，禁止新增过去日期限制。
7. 保存失败、提交中和手机结果未知重试沿用现有保护；重试不能因默认值或折叠状态改变冻结请求、产生重复任务。手机仍仅添加，不增加管理或任务列表。

## 数据与统计边界

无日期与 noTimeLimit/任务池标识必须一致；手机 API 已支持空日期及 duration=0，原则上不需要 schema 迁移。只调整本次捕获所触及的估时展示，工作量汇总明确只含已估时任务，并在相关汇总处表示未估时数量；不重建本周看板，UX-08 保留独立需求。不要修改旧版 legacy API 或接入新的同步协议。历史任务不批量重写，云端/访客规则和稳定扩展 ID 不变。

## 验收

- 普通入口只填标题：保存恰好一个任务，进入任务池，未估时；选过去日期：保存到该日。
- 明确日期入口正确继承；单纯今天视图打开普通新增不会默认为今天。
- 大任务子项不指定日期可保存、关系正确；已有排期/估时不被改写。
- 更多展开、收起、草稿关闭重开和编辑后保存不丢已填值，不触发隐藏字段拦截。
- 空估时和明确一小时可区分；统计不将未估时解释为零负担，父容器不误计。
- 手机只标题新增及重试保持幂等；登录保持、结果提示和访客本地功能无回归。
- 相关行为测试、typecheck、lint、build、发布产物核对；既有失败单独记录，不绕过。不使用未授权 GUI，Popup 窄屏、新标签宽屏和手机真人视觉待用户验收。
