# TaskMaster 产品需求文档

> 状态：当前有效
>
> 更新日期：2026-08-20
>
> 当前开发基线：3.15.1

本文档是 TaskMaster 当前产品需求的唯一 PRD。功能现状以当前工作区代码为准；发布记录见 [release-history.md](release-history.md)，未完成事项见 [open-issues.md](open-issues.md)。

## 1. 产品定义

TaskMaster 是一款面向个人用户的 Chrome 任务管理工具，目标是让用户以尽可能低的操作成本安排日常任务、查看时间分布并追踪长期执行节奏。

产品以 Chrome 扩展为主要管理端，提供工具栏弹窗和新标签页两种入口；手机网页与 Telegram 用于快速录入；Cloudflare Worker 负责多设备增量同步；公开演示页用于在不接触真实数据的情况下展示产品。

### 1.1 解决的问题

- 常规任务应用需要切换窗口或打开独立 App，记录成本较高。
- 用户需要在列表、单日、周和月等不同时间尺度之间快速切换。
- 多台设备可能长时间离线，重新联网后不能因整库覆盖而丢失任务、完成状态或删除操作。
- 手机端更适合快速录入，桌面端更适合完整整理，两端需要自然收敛。
- 用户需要看到计划投入与实际完成之间的节奏差距，而不只是任务数量。
- 用户每天需要重新决定“今天真正要完成什么”，而不是让昨天的选择自动滚入今天。
- 大任务难以直接执行，需要被拆成可独立安排和计时的下一步。
- 逾期任务必须保留风险状态，同时提供明确处理动作，避免逾期列表不断堆积后失去意义。

### 1.2 目标用户

- 主要在 Chrome 中工作的个人用户和知识工作者。
- 同时使用多台电脑，需要跨设备管理任务的用户。
- 需要在手机上快速补录待办或已完成事务的用户。
- 需要通过公开网址向他人展示 TaskMaster 的产品演示者。

### 1.3 产品价值

- **低摩擦记录**：浏览器工具栏一键打开，手机端提供最短录入路径。
- **多尺度规划**：同一批任务可在列表、日、周、月视图中管理。
- **离线可用**：本地操作不依赖网络，联网后自动收敛。
- **结果反馈**：同时呈现当前待办、今日进度、逾期风险和每周执行节奏。
- **每日执行闭环**：系统按计划日期自动形成今日清单；昨天未完成只提醒，不自动改期。
- **数据可控**：提供本地备份、文件导入导出和明确的同步状态。

## 2. 产品原则

1. **先完成目标，再展示功能**：首屏优先支持查看、添加和完成任务。
2. **系统承担同步复杂性**：正常使用不要求用户选择“保留本机还是云端”。
3. **状态必须可理解**：明确区分“已保存到本机”“正在同步”“已同步”和“同步失败”。
4. **用用户语言表达统计**：使用“统计起始日期”，不向用户暴露“锚点”等实现术语。
5. **危险动作需要保护**：任务表单有内容时，主动关闭必须确认；删除等不可逆操作需要明确反馈。
6. **公开演示与真实数据隔离**：演示页不得读取、写入或暴露真实任务和认证信息。

## 3. 产品范围

| 产品层 | 用户目标 | 当前范围 | 生效方式 |

| Chrome 新标签页 | 集中管理任务与设置 | 弹窗能力 + 逾期处理、任务拆分、分类管理、同步面板、手机同步设置 | 同一次扩展构建 |

## 4. 核心需求

### 4.1 任务管理

用户可以创建、编辑、完成、恢复和删除任务。

每条任务支持：

- 标题和描述。
- 高、中、低优先级。
- 分类。
- 计划日期或无期限状态；计划日期表示用户计划在当天开始并完成任务。
- 可选的硬截止日期；只表达外部不可延后的最后期限，不替代计划日期。
- 预计时长。
- 可选的父子关系；子任务可独立设置计划日期、硬截止日期和预计时长。
- 不重复、每日、每周、每月、工作日和自定义重复。
- 创建、修改和完成时间。

交互要求：

- 新增与编辑使用同一套表单。
- 添加或编辑时提供未来七天快捷日期，并与日期输入框双向联动。
- 无期限任务进入“任务池（无计划日期）”。
- 支持在日期区域间拖拽任务，支持双击任务进入编辑。
- 循环任务的完成操作不得因快速重复点击而推进多次。
- 表单有未保存内容时，主动关闭需要确认；点击背景不得意外丢失输入。
- 父任务只汇总子任务进度，不把父任务预计时长重复计入日、周、月和周目标统计。
- 删除父任务时必须明确提示其子任务将如何处理；默认删除父任务及其子任务。

### 4.2 今日聚焦、逾期处理与任务拆分

“今日聚焦”是扩展的默认执行视图，用于集中处理计划日期为今天的任务。

每日规则：

- 今日聚焦按本地日期判断，自动显示计划日期为今天的任务，不要求额外标记。
- 循环任务完成今天这一期后立即退出今日聚焦；任务可推进到下一循环日期，但下一期不得继续以今天的任务展示。
- 昨天未完成的任务继续保留原计划日期和红色逾期状态，并在今日聚焦顶部集中提醒。
- 系统不得把昨天未完成任务自动改为今天；用户需选择标记完成、加入今天、重新排期、拆分或放回任务池。
- 今日聚焦不显示独立的大型摘要卡，直接进入任务与逾期处理内容。
- 今日聚焦内容区使用独立面板承载：标题、说明与任务数量保持稳定留白，任务列表或空状态与标题区有明确分隔；样式不得依赖构建时可能缺失的动态工具类。
- 逾期提醒默认收起，标题显示数量，用户可展开或再次收起。
- 历史逾期区域展开后，每项任务必须形成独立、可扫描的处理卡片：标题、逾期日期与操作区分层展示，任务之间有明确分隔；操作按钮统一高度并允许自然换行，窄屏下不得粘连或溢出。
- 逾期任务标题使用与普通任务一致的常规字重，不通过加粗表达逾期；逾期状态由日期文案、区域色彩和优先级色条承担。

逾期任务必须提供五个直接动作：

- **标记完成**：直接沿用现有任务完成逻辑保存状态；成功后任务立即退出历史逾期区域。
- **加入今天**：将计划日期改为今天并加入今日聚焦；硬截止日期保持不变。
- **重新排期**：选择新的计划日期；硬截止日期保持不变。
- **拆分任务**：把原任务转换为父任务，并创建可独立安排、计时和完成的子任务。
- **放回任务池**：清除计划日期并退出今日聚焦，保留任务内容和可选硬截止日期。

任务拆分要求：

- 至少创建两个非空子任务。
- 每个子任务独立设置标题、预计时长和计划日期，之后可像普通任务一样编辑。
- 原任务转换为父任务，展示“已完成子任务 / 全部子任务”和进度条。
- 父任务不参与日历排期和时长统计；其完成状态由子任务完成进度派生。
- 子任务在列表中归属父任务，在日、周、月和今日聚焦中按自身计划日期出现。

#### 周聚焦

周视图沿用今日聚焦的核心原则：计划日期决定归属，系统不增加额外的“周聚焦”标记，也不要求用户重复选择任务。

- 自动显示计划日期落在当前所选周（周一至周日）的任务；父任务不进入排期，子任务按自身计划日期出现。
- 保留上一周、下一周、回到本周导航，以及任务在日期之间拖动、双击编辑和完成状态切换。
- 周标题展示本周任务总数与预计时长；每天展示任务数、预计时长和完成时长。
- 本周内已经过去但未完成的任务继续留在原日期，并明确标记为“本周内逾期”，不自动移动到今天。
- 当前所选周开始前仍未完成的非循环任务进入“本周开始前未完成”区域，默认折叠并显示数量。
- 历史逾期任务提供“标记完成、安排到本周、重新排期、拆分任务、放回任务池”五个动作；“安排到本周”必须先选择本周具体日期，不能只设置模糊的周归属。
- 优先级、分类、隐藏已完成和隐藏逾期等现有筛选继续生效。
- 在窄屏下日期信息与任务区上下排列，避免横向溢出。

验收标准：

- 计划日期位于周一至周日的任务无需额外操作即可出现在对应日期。
- 选择周内任意一天后，历史逾期任务的计划日期更新并立即移动到对应日期行。
- 历史逾期区域首次进入时收起，展开、再次收起均可用。
- 周日打开周视图时仍归属于即将结束的当前周，而不是错误跳到下一周。
- 修改后通过自动化检查和扩展构建；重载扩展后可在 newtab 与 popup 中使用。

### 4.3 视图、筛选与摘要

扩展支持：

- 全部任务视图（原“列表”）。
- 今日聚焦视图。
- 任务池视图。
- 日视图及前后日期导航。
- 周视图及前后周导航。
- 月视图及前后月导航。

一级导航按用户目标排列为：`今日聚焦｜任务池｜全部任务｜日｜周｜月`。任务池虽然表达任务状态，但用户进入该视图的目标是集中整理尚未排期的任务，因此与时间视图处于同一级导航。

任务池要求：

- 只显示没有计划日期的可执行任务，不显示仅用于汇总子任务进度的父任务。
- 每项任务直接提供“安排到今天、选择日期、拆分、编辑、删除”。
- “选择日期”使用现有重新排期能力；完成排期后任务立即离开任务池并出现在相应日期视图。
- “拆分”复用现有父子任务流程：至少创建两个子任务，每个子任务设置标题、预计时长和计划日期；原任务转换为只汇总进度的父任务，并退出任务池。
- 任务池操作区在宽屏保持清晰的一行排列并留出稳定间距；空间不足时，仅任务池操作区换到任务信息下方，不改变其他视图的任务行布局。
- 拆分弹窗在桌面端优先使用更充足的横向空间，标题区与操作区保持紧凑；子任务列表单独限高并在内容较多时内部滚动，避免整个弹窗被少量子任务拉得过长。
- 每个子任务编辑卡片使用紧凑的响应式布局：标题独占第一行；宽屏下第二行依次显示预计时间、未来 7 天快捷日期和自定义日期；约 400px 的扩展 Popup 中，预计时间与自定义日期并排，未来 7 天完整显示在下一行，不依赖横向滚动。
- 预计时间步进器必须使用确定宽度的减号、数值和加号三列布局，总宽度不得超过排期列，不能依赖构建时可能被裁剪的工具类控制关键尺寸。
- 拆分弹窗支持按 `Esc` 直接关闭且不提交表单。
- 任务池不使用独立筛选开关；删除筛选栏中的“任务池（无截止日期）”复选框。
- 离开任务池后不残留任何任务池筛选状态，也不改变任务数据结构和同步协议。
- 顶部导航与工具按钮组成靠右对齐的两行操作区；顶部导航在窄宽度下允许横向滚动，保持每个入口可读、可点击，不把六个入口压缩成难以识别的按钮。

筛选支持：

- 按优先级筛选。
- 按分类筛选。
- 隐藏已完成任务。
- 隐藏今日之前的任务。
- 只显示无期限任务。

顶部摘要优先展示：

- 待完成任务量或时长。
- 今日进度。
- 逾期提醒。

已完成总量不占用顶部首要位置，放在可展开的周度统计中。

### 4.4 每周目标与执行节奏

用户可以设置每周计划投入时长，并选择统计起始日期。系统基于完成任务的预计时长，展示期望投入、实际完成、执行节奏和差距。

交互要求：

- 用户可见名称统一使用“统计起始日期”或“统计起点”。
- 设置弹窗同时编辑“每周目标”和“统计起始日期”，并解释两者作用。
- 未手动设置日期时，显示当前统计实际使用的最早完成日期，避免直接保存后统计范围跳到今天。
- 每周目标以“小时 / 周”为单位，允许范围为 `0.5–168` 小时。
- 统计起始日期不得晚于今天。
- 无效输入在弹窗内说明原因，不静默替换。
- 明确提示修改起始日期只会重新计算统计，不会修改或删除任务。
- 取消或关闭设置不改变数据；保存后立即重新渲染统计。

### 4.5 分类管理

- 默认提供工作、生活和学习分类，允许新增、编辑和删除自定义分类。
- 分类支持颜色标识。
- 用户可以将一个真实分类设为默认分类。
- 星标只表达“默认”状态，不创建名为“星标”的分类。
- 未设置默认分类时，手机端选择第一个有效分类作为兜底。
- 历史 `default-starred` 分类及任务引用需要迁移到有效分类，不保留孤立引用。
- 至少保留一个分类。

### 4.6 本地存储、备份与文件迁移

- `chrome.storage.local` 是扩展端主存储和离线数据来源。
- 每次用户操作先安全保存到本机，再尝试云端同步。
- 同步面板显示当前任务数、分类数、存储用量和最近备份。
- 自动备份保留最近 3 份，用户也可立即创建和恢复备份。
- 支持 JSON 文件导出与导入，导入前验证数据格式。
- 本地保存成功不等同于云端确认成功，界面必须准确表达两种状态。

### 4.7 跨设备增量同步

任务、分类和应用设置以独立记录同步。客户端提交本地变更并按服务端游标拉取远端变更，避免整份数据互相覆盖。

同步行为：

- 离线时用户继续正常操作，恢复联网后自动同步。
- 不同任务的多端修改全部保留。
- 同一记录并发修改时，当前按整条记录的修改时间采用较新版本。
- 用户刚修改的本地应用设置必须立即获得新版本；较早发起但较晚返回的同步结果不得让复选框或其他设置短暂跳回旧值。
- 删除以墓碑记录同步，旧设备重新联网后不得复活已删除内容。
- 手动“上传到云端”和“从云端拉取”都会触发一次增量收敛，不直接覆盖另一端未同步的数据。
- 首次使用新协议时，Worker 将旧版 `full_sync` 快照迁移为增量记录。
- 旧版 `/api/fullsync` 接口保留兼容，但不得覆盖已进入增量协议的数据。

同步状态至少包含：

- 正在保存。
- 已保存到本机，等待云同步。
- 已确认同步到云端。
- 同步失败及可操作的错误反馈。

### 4.8 手机快速添加

手机页通过 Worker 提供，用户配置 API 地址和密钥后可以快速添加任务。

表单支持：

- 标题和描述。
- 优先级。
- 由扩展同步而来的实际分类，并自动选择默认分类。
- 截止日期或无期限。
- 预计时长。
- 添加时标记为已完成。

已完成状态要求：

- 控件整行可点击，放在预计时长之后。
- 未选中时明确显示“未完成”。
- 选中后使用绿色完成态、勾选图标和结果文案。
- 提交后写入完成状态与完成时间，电脑端同步后保持已完成。
- 提交成功后重置已完成控件，避免下一条任务被误标记。

手机页属于远程服务，修改 `shared/*.ts` 不会使手机端生效；必须修改 `backend/index.js` 中的移动页面并部署 Worker。

### 4.9 Telegram 快速录入

- 用户通过 `/token` 绑定 API 密钥。
- 普通消息可解析任务标题、相对或具体日期、优先级和分类。
- 解析后的任务进入手机任务队列，由扩展拉取并确认。
- Telegram 是可选入口，不影响网页和扩展的核心使用。

### 4.10 公开演示页

公开演示页打开后第一屏直接显示可操作的 TaskMaster，不设置营销中转页。

功能范围：

- 使用虚构预填任务展示今天、未来、已完成、逾期和无期限状态。
- 展示分类、优先级、日期、时长和每周目标。
- 支持搜索、分类筛选、优先级筛选和隐藏已完成。
- 支持列表、今日和周视图。
- 支持切换完成状态、新增临时演示任务和一键重置。
- 新增和修改只存在于当前页面内存，刷新后恢复初始样例。

数据边界：

- 不连接 Worker、D1、扩展存储或第三方 API。
- 不使用 LocalStorage、IndexedDB、Cookie 或服务端数据库。
- 不包含 API Token、真实任务标题或真实用户标识。
- Content Security Policy 禁止向外部 API 建立连接。

部署要求：

- 可直接由静态服务器托管。
- 提供 Docker/Nginx 部署配置和 `/healthz` 健康检查。
- 桌面与手机宽度下均不得出现横向溢出、文字遮挡或不可点击控件。

## 5. 视觉与交互规范

### 5.1 扩展端

- 调性：简洁、紧凑、工作导向，优先保证信息密度和操作清晰度。
- 主色：蓝色用于主要操作和当前状态；红、黄、绿用于风险、优先级和成功反馈。
- 布局：白色或深色表面、灰色层级、圆角控件和轻量阴影。
- 主题：支持亮色和深色模式。
- 反馈：保存、同步、导入、备份和错误都必须提供即时状态。
- 可达性：按钮使用明确标签或标题，表单错误不能只依赖颜色。

### 5.2 手机端

- 使用单列、紧凑、触控友好的表单。
- 主要提交动作始终清晰可见。
- 设置与录入逐步展示，不让首次录入被配置细节淹没。
- 状态选择使用整行反馈，不依赖难以识别的小型原生复选框。

### 5.3 公开演示页

- 桌面端使用左侧分类导航和主任务区。
- 移动端转换为顶部筛选和单列任务流。
- 明确显示“公开演示”和“数据不会同步”，但不增加长篇说明。
- 颜色用于表达分类、优先级、完成和风险，不以装饰为目的。

## 6. 技术与数据约束

### 6.1 架构边界

| 层级 | 权威源码 | 数据或职责 | 上线方式 |
| --- | --- | --- | --- |
| Chrome 扩展 | `shared/*.ts`、入口 HTML、`styles/` | 任务管理、本地存储、渲染与同步客户端 | `npm run build` 后重载 `chrome-extension-sync/` |
| 手机页与 API | `backend/index.js` | 移动页面、任务接口、Telegram 和同步接口 | 在 `backend/` 部署 Worker |
| 云端数据 | Cloudflare D1 | `pending_tasks`、`sync_records`、`sync_changes` 等 | 执行兼容的 schema 或增量迁移 |
| 公开演示 | `demo/` | 仅虚构样例和内存交互 | 静态服务器或 `deploy/demo/` |

### 6.2 Chrome 扩展约束

- 使用 Chrome Extension Manifest V3。
- 禁止 HTML 内联事件处理器，统一使用 `addEventListener`。
- 隐藏文件输入框时使用透明和绝对定位，不使用 `display: none`。
- 本地日期由 `Date` 的年、月、日手动格式化，不使用会转换 UTC 的 `toISOString()`。
- `manifest.json` 必须保留稳定的 `key`，确保扩展 ID 一致。
- 根目录和 `chrome-extension-sync/` 中的构建产物由现有构建流程生成，不手工维护。

### 6.3 同步与安全约束

- API 使用 `Authorization: Bearer <token>`，不把密钥放入 URL。
- Worker 未配置 `API_TOKEN` 时拒绝受保护请求。
- 分类读取、任务写入和同步接口均需认证。
- 同步历史和删除墓碑在设备确认机制完成前不得按时间直接清理。
- 同步失败不得阻止本地使用，也不得把未确认的云同步显示为成功。

## 7. 当前验收标准

### 7.1 扩展端

- 可以在弹窗和新标签页完成任务新增、编辑、完成、恢复和删除。
- 四种视图、日期导航、筛选、任务池、拖拽和深色模式可用。
- 今日聚焦自动识别计划日期为本地今天的任务，不依赖额外聚焦标记。
- 昨天未完成只提醒且保持逾期红色状态，逾期区域可展开和收起。
- 逾期任务可加入今天、重新排期、拆分或放回任务池，每个动作立即更新界面。
- 计划日期和硬截止日期含义清晰且可独立编辑；重新排期不修改硬截止日期。
- 父任务展示子任务进度，子任务可独立排期和计时，父任务不重复计入任何时长统计。
- 快捷日期不会产生 UTC 时区偏移。
- 周度目标设置使用“统计起始日期”，错误范围无法保存。
- 表单不会因点击背景意外关闭，有内容时主动关闭会提示。
- 分类默认状态、备份、导入导出和同步反馈正确。

### 7.2 同步

- 两台离线设备分别新增任务，联网后两条任务都存在。
- 一台设备删除任务后，旧设备同步不会将其复活。
- 两台设备修改不同任务，联网后两处修改都保留。
- 同一任务并发编辑时采用较新的整条记录。
- 旧版快照首次访问增量接口后可以迁移。
- 本地保存、云端确认和失败状态不会互相混淆。

### 7.3 手机端

- 分类接口返回真实分类并正确选择默认分类。
- 无默认分类时存在稳定兜底，不出现 `default-starred` 孤立引用。
- 待办和已完成任务都能创建，完成时间可以同步到电脑端。
- 已完成控件状态清晰，提交成功后正确重置。
- 修改后通过 Worker 部署到用户实际访问的页面。

### 7.4 公开演示

- 不依赖 Chrome 扩展 API即可打开和操作。
- 不向 Worker 或第三方 API 发请求。
- 搜索、筛选、视图、完成、新增和重置可用。
- 刷新后恢复虚构样例数据。
- Docker 容器提供 `/healthz`。

### 7.5 工程验证

- `npm run check` 通过。
- `npm run build` 通过。
- 源码、包和可加载扩展目录的版本一致。

## 8. 已知边界与非目标

### 8.1 已知边界

- 同一任务的不同字段被两台设备同时修改时，当前按整条记录最后修改优先，不做字段级合并。
- `sync_changes` 和删除墓碑暂不自动清理，避免长期离线设备导致数据复活。
- `workers.dev` 在部分网络环境中可能无法直接访问，网络可达性不由扩展本身保证。

### 8.2 当前非目标

- 团队协作、多人账号和权限系统。
- 让公开演示页访问真实任务。
- 为演示页增加登录、数据库或持久化。
- 在设备确认机制完成前清理同步历史。
- 用复杂冲突弹窗替代自动收敛。

## 9. 竞品参考

- **Todoist**：参考快速添加、清晰任务层级和筛选反馈。
- **TickTick**：参考列表与日期视图、完成统计和任务拆解的组合方式。
- **Microsoft To Do**：参考 My Day 每日重新选择的低学习成本交互，但不自动把昨日任务加入今天。
- **Things 3**：参考“今天”作为执行承诺而非全部到期任务的聚焦方式。
- **Notion 的离线同步思路**：参考本地缓存、变更记录和自动收敛，不复制其文档协作模型。

竞品只用于验证交互模式，不扩张 TaskMaster 的个人任务管理定位。
